## 三层协作 Skill 触发规则（v1.3）

当用户在当前聊天直接发送“添加总控身份”，或要求管理、恢复、迁移、检验本项目已登记的三层协作时，先加载并完整读取已安装的 `three-tier-collaboration` Skill 及其引用的架构规则，再处理当前任务。必要时按名称查找 Skill；不可用时明确说明缺失，不得假装已经加载。

若当前会话已核验登记为该架构的总控或直属成员，本项目后续每轮任务继续遵守 Skill，不因用户未重复技能名或架构口令而跳过。版本变化、尚未加载或上下文不确定时，先重新读取 Skill 与相关规则。已登记总控在实质检索、分析、编程、计算或内容改写前，必须先向匹配的已有直属子会话实际派发；修改派回原负责会话。改变研究问题、数据范围、方法、机制、结论或问题层级，均不能以“简单”“报告结构调整”为由自行执行。总控可做协调、关键验收和已验收内容的机械整合；用户明确指定总控亲自完成的具体任务可例外。缺下级、授权或工具时说明具体缺口，不静默接管。无派发及下级本轮成果证据，不把依赖下级执行的任务标为完成。

仅讨论、引用、转换或审阅规则文件不构成启用。启用必须核验：当前聊天名称严格为“总控”、用户直接发送口令、真实会话 ID 和项目登记。已有登记下级依据可核验的直属关系与用户授权履职。加载本触发段不授予身份、新建会话、通信、迁移或模型调用权限；具体授权与能力限制仍按完整 Skill 和平台规则核验。普通未启用聊天保持普通工作方式。
